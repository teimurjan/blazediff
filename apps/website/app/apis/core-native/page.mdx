# @blazediff/core-native

import { Callout } from "nextra/components";

The fastest single-threaded image diff in the world. Native Rust implementation with SIMD optimization, **4.3-4.9x faster** and **3x smaller** than [odiff](https://github.com/dmtrKovalenko/odiff).

[View Detailed Benchmarks](https://github.com/teimurjan/blazediff/blob/main/BENCHMARKS.md)

<Callout type="warning">
  This package was previously published as [`@blazediff/bin`](https://www.npmjs.com/package/@blazediff/bin), which is now deprecated. Please use `@blazediff/core-native` instead.
</Callout>

## Installation

```sh npm2yarn
npm install @blazediff/core-native
```

Also available as a Rust crate: [`cargo install blazediff`](https://crates.io/crates/blazediff)

Pre-built binaries are included for all major platforms - no compilation required:
- macOS ARM64 (Apple Silicon) & x64 (Intel)
- Linux ARM64 & x64
- Windows ARM64 & x64

## Features

- **PNG, JPEG & QOI support** - auto-detected by file extension or encoded bytes
- **4.3-4.9x faster** than odiff, **3x smaller** binaries (~700KB-900KB vs ~2-3MB)
- **SIMD-accelerated** - NEON on ARM, SSE4.1 on x86
- **Block-based optimization** - skips unchanged regions
- **Interpret mode** - region detection, classification, severity scoring, human-readable summaries

### Vendored Libraries

- [libspng](https://libspng.org/) - Fast PNG decoding/encoding with SIMD
- [libjpeg-turbo](https://libjpeg-turbo.org/) - High-performance JPEG codec with SIMD
- [qoi](https://github.com/aldanor/qoi-rust) - QOI (Quite OK Image) format for fast lossless compression

## API Reference

### `diff(a, b, options?)`

Compares two images and optionally draws the diff. It takes the same options and returns the same result as [`@blazediff/core`](/apis/core), with wider inputs and outputs. Each side is a file path, encoded PNG, JPEG or QOI bytes (a `Buffer` works), or raw RGBA pixels `{ data, width, height }`. The two sides can use different kinds.

##### Options

| Option         | Type                                       | Default   | Description |
| -------------- | ------------------------------------------ | --------- | ----------- |
| `threshold`    | `number`                                   | `0.1`     | Color difference threshold (0-1). Lower is stricter |
| `antialiasing` | `boolean`                                  | `true`    | Detect anti-aliased pixels and leave them out of the count |
| `metric`       | `"yiq" \| "oklab"`                         | `"yiq"`   | Color metric. `"oklab"` gives the same counts as pixelmatch 8 |
| `mask`         | `Uint8Array`                               | -         | One byte per pixel (width × height). Non-zero pixels are skipped. Needs the N-API binding |
| `window`       | `number`                                   | -         | Also report the N×N window with the most diff pixels |
| `output`       | `string \| Image \| { path, compression?, quality? }` | - | A file path (PNG compression 0-9, JPEG quality 1-100), or an `Image` filled in place. A file is not written when the images are identical |
| `render`       | `{ alpha?, diffColor?, diffColorAlt?, aaColor?, background? }` | - | Output styling, as in `@blazediff/core` |

#### Result

```typescript
type NativeDiffResult =
  | { kind: "compared"; count: number; percentage: number; identical: boolean;
      window?: { x: number; y: number; count: number } }
  | { kind: "dimension-mismatch"; a: Size; b: Size }
  | { kind: "io-error"; path?: string; message: string };
```

Invalid options or buffers throw a `BlazeDiffError` with a `code`, as in `@blazediff/core`.

<Callout type="info">
  Encoded inputs are passed by reference across the N-API boundary. Rust borrows
  the existing JavaScript backing memory for the synchronous call. Image decoding
  still allocates native RGBA pixel buffers.
</Callout>

<Callout type="info">
  **Threshold Guidelines:**
  - `0.0` - Exact match only
  - `0.05` - Strict comparison
  - `0.1` - Default balanced comparison
  - `0.2` - Lenient comparison
</Callout>

## Usage

### Programmatic API

```typescript
import { diff } from '@blazediff/core-native';

const result = await diff('expected.png', 'actual.png', {
  output: 'diff.png',
  threshold: 0.1,
});

if (result.kind === 'compared') {
  if (result.identical) console.log('Images are identical!');
  else console.log(`${result.count} pixels differ (${result.percentage.toFixed(2)}%)`);
} else if (result.kind === 'dimension-mismatch') {
  console.log('Images have different dimensions');
} else {
  console.log(`Could not read ${result.path}: ${result.message}`);
}
```

### Encoded Buffer Input

```typescript
import { readFile } from "node:fs/promises";
import { diff } from "@blazediff/core-native";

const [expected, actual] = await Promise.all([
  readFile("expected.png"),
  readFile("actual.png"),
]);

// Reuse these same Buffer objects across comparisons without a JS-to-Rust copy.
const result = await diff(expected, actual, { output: "diff.png" });
```

### CLI Usage

```bash
# Compare two PNG images and write the diff
npx blazediff expected.png actual.png -o diff.png

# Compare two JPEG images
npx blazediff expected.jpg actual.jpg -o diff.jpg

# Mixed formats (PNG input, QOI output - recommended for smallest diff files)
npx blazediff expected.png actual.png -o diff.qoi

# Stricter threshold, anti-aliased pixels counted
npx blazediff expected.png actual.png -o diff.png --threshold 0.05 --no-antialiasing

# pixelmatch 8 metric and the busiest 16×16 window, as JSON
npx blazediff expected.png actual.png --metric oklab --window 16 --json

# With higher PNG compression (smaller output file, slower)
npx blazediff expected.png actual.png -o diff.png -c 6
```

### CLI Options

```bash
Usage: blazediff [OPTIONS] <A> <B>

Options:
  -o, --output <OUTPUT>            Write the diff image here (only when the images differ)
  -t, --threshold <THRESHOLD>      Color difference threshold (0.0-1.0) [default: 0.1]
      --antialiasing               Detect anti-aliased pixels and leave them out of the count (default)
      --no-antialiasing            Count anti-aliased pixels as differences
      --metric <METRIC>            Color difference metric: yiq or oklab (pixelmatch 8) [default: yiq]
      --mask <MASK>                Image the size of the inputs; its non-black pixels are skipped
      --window <WINDOW>            Also report the N×N window with the most diff pixels
  -a, --alpha <ALPHA>              Opacity of the faded background (0.0-1.0) [default: 0.1]
      --diff-color <R,G,B>         RGB color for differing pixels
      --diff-color-alt <R,G,B>     RGB color for pixels that get darker in the second image
      --aa-color <R,G,B>           RGB color for anti-aliased pixels
      --background <BACKGROUND>    faded or transparent [default: faded]
  -c, --compression <COMPRESSION>  PNG compression level (0-9) [default: 0]
  -q, --quality <QUALITY>          JPEG quality (1-100) [default: 90]
      --json                       Print the result as JSON
  -h, --help                       Print help
  -V, --version                    Print version
```

`--json` prints the result object, for example `{"kind":"compared","count":121,"percentage":0.09,"identical":false}`.

### Supported Formats

| Format | Extensions | Notes |
|--------|------------|-------|
| PNG | `.png` | Lossless, supports transparency |
| JPEG | `.jpg`, `.jpeg` | Lossy, smaller file sizes |
| QOI | `.qoi` | Fast lossless, ideal for diff outputs (12x smaller than uncompressed PNG) |

Input images can be mixed formats (e.g., compare PNG to JPEG). Output format is determined by the output file extension.

<Callout type="tip">
  **Use QOI for diff outputs:** QOI excels at encoding diff images with large uniform areas, producing files 12x smaller than PNG (level 0) while being faster to encode.
</Callout>

### Exit Codes

- `0` - Images are identical
- `1` - Images differ (includes layout/size mismatch)
- `2` - Error (file not found, invalid format, etc.)

### Interpret

Structured region analysis is a separate package. This one answers *where*
pixels differ; [`@blazediff/interpret-native`](/apis/interpret-native) takes the
same pair and describes *what* changed — labelled regions, severity and a
human-readable summary — and can locate those regions with a pixel diff, an SSIM
map, or boxes you already have.

```typescript
import { interpret } from '@blazediff/interpret-native';

const result = await interpret('expected.png', 'actual.png');
console.log(result.summary);
// "Moderate visual change detected (1.87% of image, 4 regions).
//  Content changed: 1 region (bottom).
//  Content added: 2 regions (right, bottom-left)."
```

See [Interpret example →](/docs/difference-analysis) for the interactive demo.

## Performance

Benchmarked on Apple M1 Max with 5600×3200 4K images (25 runs, 5 warmup, image IO included):

| Tool | Time | Comparison |
|------|------|------------|
| **blazediff** (`BLAZEDIFF_PNG_ENABLED=1`) | ~190ms | - |
| **blazediff** (file paths) | ~274ms | - |
| odiff | ~1239ms | 4.5x slower |

These are end-to-end times, so PNG decode and encode take most of them. The diff
itself is faster than in 7.0.0. On a 3598x16384 page screenshot, a count-only diff
takes 11 ms instead of 38 ms, and a diff that writes an image is about 3.5x faster.
That gain is small in this table because IO is the larger share of the total.
`BLAZEDIFF_PNG_ENABLED=1` routes PNG decode and stored-block (level 0) encode
through the in-house [`blazediff_png`](https://crates.io/crates/blazediff-png) codec.

Binary sizes (stripped, LTO optimized):

| Platform | blazediff | odiff |
|----------|-----------|-------|
| macOS ARM64 | 702 KB | 2.2 MB |
| Linux x64 | 869 KB | 2.9 MB |
| Windows x64 | 915 KB | 3.0 MB |

<Callout type="info">
  **Why so fast?** BlazeDiff walks the image one band at a time. A band is one row of blocks, and the block size grows with the image area, from 8 to 128 pixels. A SIMD scan reads the band in pixel-row order and flags each block that holds a pixel over the threshold. An integer bound derived from the YIQ metric's largest eigenvalue rejects most sub-threshold pixels before any floating-point work. The hot pass then runs the YIQ delta and the anti-aliasing check on the flagged blocks only, while the band is still in the CPU cache. The other blocks get the gray background in one vectorized write. The N-API binding diffs raw RGBA input in place and draws into your output buffer, so it does not copy either one.
</Callout>
